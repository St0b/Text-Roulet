# GreenOS 2.5 — Linux Edition

Рабочий стол в браузере с **настоящим Linux в эмуляторе x86/v86**. Машинный код гостевой системы исполняется через WebAssembly. Это не JavaScript-имитация команд Linux.

## Запуск

Нужен Python 3.10+ и современный браузер с WebAssembly и IndexedDB.

```powershell
python main.py
```

Откроется [http://127.0.0.1:8000](http://127.0.0.1:8000). Для другого порта или запуска без открытия браузера:

```powershell
python main.py --port 8080 --no-browser
```

Для локального запуска оболочки и Linux дополнительные Python-пакеты не нужны. Эмулятор, BIOS, терминал и два образа уже находятся в `frontend/static/`. После скачивания проекта запуск Linux не требует CDN; работа сетевых приложений и чата зависит от сети и сервера.

Flask/Vercel и Supabase используют зависимости из `requirements.txt`:

```powershell
python -m pip install -r requirements.txt
```

## Как запустить Linux

В приветственном окне нажмите **«Запустить Linux»** или **«Графический Linux»**. Можно открыть приложение Linux из меню.

| Режим | Что загружается | RAM по умолчанию |
| --- | --- | --- |
| Buildroot | Linux 6.8, BusyBox, настоящая интерактивная оболочка, vi, Lua | 128 МБ |
| Tiny Core | Tiny Core Linux 11, ядро 5.4.3, графическая среда FLWM | 256 МБ |
| Свой образ | Пользовательский 32-битный x86 ISO или IMG | 256 МБ |

Buildroot обычно загружается за несколько секунд. Первая загрузка Tiny Core может занимать **1–3 минуты** в зависимости от устройства; загрузчик запускается автоматически. Вкладка **«Экран компьютера»** показывает экран и графические программы гостевой системы. Нажмите на экран для управления мышью и клавиатурой. В Buildroot удобнее вкладка **«Консоль Linux»**.

Дистрибутив и RAM выбираются в верхней панели. Кнопка с круговой стрелкой рядом с паузой запускает машину заново с выбранными параметрами. Перед заменой работающей машины появится подтверждение. Свой образ выбирается через шестерёнку → **«Выбрать ISO / IMG»**. Максимальный размер пользовательского образа — 512 МБ.

Примеры команд в Buildroot:

```sh
uname -a
id
ls /bin
ps
printf 'Hello from Linux\n' > /mnt/hello.txt
cat /mnt/hello.txt
vi /mnt/hello.txt
lua -v
```

Buildroot — минимальная система без `apt`, `apk` или `pacman`. Установка пакетов и набор программ зависят от выбранного дистрибутива. v86 исполняет **32-битный x86**; 64-битные образы и программы не поддерживаются.

## Файлы и сохранение

Есть два независимых хранилища:

- **Файлы GreenOS** — папки и документы в IndexedDB браузера. Поддерживаются создание, переименование, перенос между папками, поиск, корзина и восстановление, загрузка с компьютера, скачивание, просмотр изображений/аудио/видео и текстовый редактор. Двойной клик по папке меняет каталог в текущем окне. Запуск «Файлов» или «Домашней папки» открывает отдельное окно. Кнопка «Рядом» размещает два окна для перетаскивания. Файл также можно перенести через «Вырезать» и «Вставить».
- **Linux** — память, процессы и гостевая файловая система виртуальной машины. **«Снимок»** сохраняет состояние в IndexedDB. **«Восстановить»** загружает последний снимок выбранного дистрибутива. **«Экспорт»** скачивает `.gvm`, **«Импорт»** восстанавливает его, включая пользовательский образ, если он использовался.

В Buildroot общая файловая система 9p уже смонтирована в **`/mnt`**:

1. В файловом менеджере выберите файл → «Действия» → **«Отправить в Linux /mnt»**.
2. В Linux откройте `/mnt/имя-файла`.
3. Для обратного копирования нажмите **«Из Linux»** и укажите путь, например `/mnt/hello.txt`. Файл появится в папке **«Обмен с Linux»**.

При новом запуске Buildroot файлы из папки «Обмен с Linux» копируются в `/mnt`. Последующие изменения передаются явно; автоматического объединения или синхронного удаления нет. Через 9p доступны файлы общего каталога, а не произвольный путь внутри гостевого `/etc` или `/home`. В других образах с поддержкой 9p его можно смонтировать вручную:

```sh
mkdir -p /mnt/greenos
mount -t 9p -o trans=virtio,version=9p2000.L host9p /mnt/greenos
```

Снимок Linux нужно сохранить **до перезагрузки или закрытия страницы**. Закрытие окна Linux останавливает машину; оно требует подтверждения. Сворачивание оставляет машину работающей. Окна, их расположение, рабочие пространства и черновики редактора восстанавливаются после обновления страницы; сама Linux ждёт явного запуска или восстановления снимка.

Сохранённые снимки можно включить в резервную копию рабочего пространства GreenOS. Для отдельного переноса снимка Linux используйте `.gvm`. При загрузке снимка GreenOS проверяет совместимость с сохранённой версией v86.

## Сеть

В параметрах Linux доступны три режима: HTTP через браузер, WebSocket relay и отключённая сеть. Сеть выбирается перед запуском или применяется при перезапуске.

Режим HTTP использует backend `fetch` v86. В Buildroot включите DHCP командой `udhcpc`; доступ к HTTP ограничивается CORS и правилами браузера. Это не полный TCP/IP-доступ в Интернет. Для полноценного сетевого доступа укажите свой совместимый `ws://` / `wss://` relay; публичный сторонний relay автоматически не подключается. На HTTPS-странице нужен защищённый `wss://` relay. [Сетевая документация v86](https://github.com/copy/v86/blob/master/docs/networking.md).

Приложение «Интернет» открывает адреса и закладки в окне GreenOS. Текстовый запрос ищет статьи в Википедии. Кнопки «Назад» и «Вперёд» переключают введённые адреса и запросы. Сайты, которые запрещают встраивание, могут не отобразиться. В графическом Linux приложения используют сеть виртуальной машины.

В приложении «Радио» доступны Radio Paradise и Radio Record. Можно ввести прямой адрес аудиопотока или плейлиста HLS `.m3u8`. На HTTPS-странице для потока тоже нужен HTTPS. Свёрнутое окно продолжает играть. Кнопка «Остановить» и закрытие окна отключают поток. Установленная громкость сохраняется после закрытия окна и перезагрузки страницы.

## Рабочий стол

Кнопка «Обзор» в верхней панели показывает открытые и свёрнутые окна по рабочим пространствам. Нажмите на окно, чтобы переключиться к нему.

Окна плавно сворачиваются к панели задач и восстанавливаются из неё. Разворачивание и возврат к прежнему размеру тоже анимированы. Движение можно отключить в настройках оформления GreenOS или в системной настройке уменьшения движения.

В меню приложений есть GreenBlocks, воксельная игра с миром 80 × 80 × 32 блока на WebGL 2. В режиме «Экспедиция» игрок проходит пять этапов от первых инструментов до постройки поселения и маяка. Маяк открывает полёт.

- **Инвентарь (E).** Сетка 2×2 для досок, палок, факелов и верстака, рюкзак и журнал экспедиции. Предметы можно перетащить из рюкзака на быструю панель из девяти ячеек или выбрать предмет и нажать ячейку. ПКМ по ячейке возвращает предмет в рюкзак.
- **Верстак.** Поставь его в мире и открой ПКМ. Сетка 3×3 нужна для кирок, мечей, мотыги, хлеба, печи, фонарей и маяка. Схемы помогают разложить ингредиенты. Чтобы забрать предмет, нажми на результат.
- **Печь.** Открой установленную печь ПКМ. Железная руда превращается в слитки, сырая свинина жарится, стволы дают древесный уголь, а песок обжигается в кирпичи. Деревянная кирка добывает каменный уголь из жил. Содержимое хранится отдельно в каждой печи, а плавка идёт и при закрытом меню печи, пока открыт мир.
- **Выживание.** Ночью появляются зомби, а факелы, фонари и маяки освещают ближайшие блоки. Сытость восстанавливается едой с быстрой панели по ПКМ. Здоровье восстанавливается при высокой сытости, падение и долгое погружение наносят урон. При возрождении вещи остаются в сундуке на месте гибели. Сложность «Мирная» убирает зомби и поддерживает сытость.
- **Земледелие.** Семена иногда выпадают из дёрна. Вспаши открытую землю мотыгой по ПКМ, посади семена по ПКМ и собери спелую пшеницу. Рост требует света и ускоряется рядом с водой. Из трёх колосьев можно испечь хлеб на верстаке.

В творческом режиме доступны восемь материалов с бесконечным запасом и полёт с самого начала. У каждого режима свой мир и своё сохранение в браузере. Существующий мир GreenBlocks открывается через кнопку «Творческий» на экране паузы.

WASD или стрелки управляют ходьбой, двойное W — бегом, пробел — прыжком и всплытием. Левая кнопка мыши атакует моба в пределах досягаемости или начинает добычу блока. Правая использует выбранный предмет или открывает станцию. Shift + ПКМ позволяет поставить блок рядом со станцией. Клавиши 1–9 (1–8 в творческом режиме) и колесо выбирают слот. Esc ставит игру на паузу. F переключает полёт, а пробел и Shift меняют высоту.

Окна поддерживают перемещение, изменение размера, разворачивание, сворачивание и перенос на одно из трёх рабочих пространств. Окна одного приложения в текущем пространстве собраны в группу на панели задач. Щелчок по группе показывает список окон. При загрузке GreenOS показывает заставку и экран разблокировки. Мелодия звучит при разблокировке, если включён звук запуска. Экран блокировки скрывает интерфейс. Пароли Linux настраиваются внутри гостевой ОС.

Тема и акцент применяются к панели задач, верхней панели, ярлыкам, меню и окнам. В **Настройки → Оформление → Добавить обои** можно загрузить свои PNG, JPEG и WebP до 15 МБ. Галерея и выбранный фон сохраняются в браузере. В **Настройки → Пользователь** можно загрузить или удалить локальный аватар. Аватар отображается в меню приложений и на экране блокировки.

На рабочем столе ПКМ открывает команду **Добавить ярлык приложения…**. В меню файла или папки есть команда **Создать ярлык на рабочем столе**. Ярлыки перетаскиваются по сетке, их позиции сохраняются. Команда **Убрать ярлык** и клавиша Delete удаляют только ссылку с рабочего стола.

Приложение **Документы** открывает локальные PDF, Word (.docx), PowerPoint (.pptx) и Excel (.xlsx). Его можно запустить из меню или двойным щелчком по документу в приложении «Файлы». Встроенный просмотр PDF зависит от браузера.

- **Word.** Создай новый DOCX или открой копию существующего файла для редактирования. Доступны листы A4, просмотр двух страниц рядом и режим «Черновик». Enter после центрированного текста начинает новый абзац у левого края. Ctrl+Enter вставляет разрыв страницы, Ctrl+F открывает поиск и замену. Можно менять шрифт, цвет, начертание, выравнивание и межстрочный интервал, вставлять списки, таблицы и изображения. Сложная вёрстка в копии импортированного файла может отличаться от исходника.
- **Excel.** Создавай книги XLSX и редактируй значения и формулы в копии существующей книги. Используй кнопки перехода по строкам и столбцам, поле адреса ячейки или Ctrl+End в сетке, чтобы добраться до конца заполненной области. Щелчок по заголовку выделяет столбец, Shift+щелчок выделяет диапазон столбцов на текущей странице. Шрифт, кегль и полужирное начертание сохраняются в XLSX для ячейки или выбранных столбцов. GreenOS вычисляет арифметику, ссылки A1 внутри листа и функции SUM, AVERAGE, MIN, MAX и COUNT. При сохранении значений книга помечается для пересчёта в Excel. Массивы, общие и другие специальные формулы защищены от перезаписи.
- **PowerPoint.** В копии PPTX можно менять текстовые фрагменты слайдов.
- **Сохранение.** Ctrl+S записывает документ в папку «Документы» GreenOS. Кнопка скачивания выгружает результат в DOCX, PPTX или XLSX. Исходные файлы при редактировании сохраняются отдельно.

Встроенные приложения включают Linux, Файлы, редактор, Документы, просмотр медиа, Радио, калькулятор, системный монитор, настройки, Интернет и Text Roulette. В приложении «Игры» доступны 2048, Сапёр, Змейка, Реверси и Пятнашки.

**«Галактика».** На карте кампании шесть сюжетных секторов с волнами противников и флагманами. Сектора можно проходить повторно и собирать лом для ангара. Там улучшаются оружие, броня, двигатель и сборщик. Ресурсы начисляются по завершении вылета. Прогресс кампании сохраняется в браузере. В отдельной бесконечной аркаде действует свой рекорд. Кораблём управляют WASD или стрелки, пробел открывает огонь, P ставит игру на паузу. Перетаскивание мышью или пальцем одновременно двигает корабль и стреляет.

| Клавиши | Действие |
| --- | --- |
| Alt+F1 | Меню приложений |
| Alt+Tab | Следующее окно |
| Alt+F4 | Закрыть активное окно |
| Ctrl+Alt+1 / 2 / 3 | Рабочее пространство |
| Ctrl+S | Сохранить документ в активном редакторе |

Некоторые сочетания может перехватывать операционная система компьютера; те же действия доступны кнопками.

## Центр восстановления

Откройте **«Центр восстановления»** из меню приложений или через **Настройки → Данные**. Черновики остаются доступны после перезапуска, а окно центра открывается по запросу.

- **Черновики Office.** Word, Excel и PowerPoint записывают правки в IndexedDB примерно через полсекунды после изменения. Когда появится отметка «Черновик сохранён», эти правки доступны для восстановления. В Word сохраняются оформление и изображения, в Excel сохраняется даже незавершённый ввод в текущей ячейке. После явного сохранения черновик исчезает из списка. Восстановленный документ сохраняется как отдельная копия. Если сохранённая версия файла изменилась в другой вкладке, можно сохранить свои правки новой копией. История отмены хранится только в открытом редакторе.
- **Резервная копия `.greenos`.** Нажмите «Скачать резервную копию», чтобы выгрузить файлы, корзину, настройки, ярлыки, оформление, сеанс, поддерживаемые игровые сохранения и черновики. Отдельная галочка включает сохранённые снимки Linux. Перед заменой данных GreenOS проверяет содержимое копии и показывает её сводку. Закройте другие вкладки GreenOS перед импортом. Для переноса выберите «Восстановить из копии…» в другом профиле браузера.
- **Отдельный архив файлов.** В «Настройки → Данные» по-прежнему доступны экспорт и импорт JSON только для файлов. Данные GreenOS хранятся в профиле браузера для текущего адреса сайта. Храните загруженную резервную копию отдельно, если планируете очистить данные сайта.

## План GreenOS 3.0

1. **Устанавливаемый рабочий стол.** Запуск оболочки и локальных приложений без интернета после первой загрузки. Образы Linux для офлайн-режима загружаются отдельно по выбору пользователя.
2. **Управление данными.** Версии файлов, поиск по рабочему пространству и восстановление предыдущих правок. Отдельные локальные профили и зашифрованные резервные копии. Синхронизацию между устройствами стоит проектировать после проверки работы версий и разрешения конфликтов.
3. **Связанные приложения.** Общие команды «Открыть с помощью», «Недавние файлы» и системный поиск. Для Office приоритетом станет сохранение исходного оформления при цикле «открыть, изменить, сохранить», а для Linux — устойчивый обмен файлами между гостевой системой и рабочим столом.

Перед релизом 3.0 нужно проверить обновление с 2.5 с сохранением файлов и настроек, запуск рабочего стола без сети, перенос в чистый профиль и параллельное редактирование. Эти сценарии должны проходить в браузерах, заявленных для релиза.

## Структура и проверка

`frontend/index.html` — оболочка, `frontend/static/*.js` — отдельные модули окон, файловой системы, Linux и приложений. `server.py` обслуживает локальные HTTP/API-маршруты, `api/index.py` — Flask/Vercel. Text Roulette использует существующий backend и при необходимости Supabase; настройка описана в `SUPABASE_SETUP.md`.

В `vercel.json` образы, WASM и другие `/assets/` отдаются как статические файлы через CDN, а не в теле ответа Python-функции. `.vercelignore` исключает локальное окружение и артефакты тестирования из загрузки. Публикация на Vercel выполняется отдельно; локальная проверка Flask не заменяет проверку развёртывания.

```powershell
node tools/test_linux.cjs
python -m unittest discover -s tests
```

Первый тест действительно загружает Linux, выполняет команды, проверяет обмен файлами и сохранение/восстановление состояния. Он требует Node.js с WebAssembly. Серверные тесты используют стандартную библиотеку Python; Flask-тесты дополнительно запускаются при наличии Flask.

Браузерные сценарии из папки `tools/` используют Playwright, установленный отдельно. Они проверяют рабочий стол, Linux, GreenBlocks, оформление, ярлыки, игры, просмотр и сохранение документов Office. Сценарий `node tools/test_recovery_center.cjs` дополнительно проверяет восстановление после сбоя вкладки и перенос в чистый профиль Chromium. Артефакты проверки сохраняются в игнорируемой папке `test-results/`.

Версии и SHA-256 сторонних ресурсов зафиксированы в `frontend/static/runtime-lock.json`. При необходимости `python tools/fetch_runtime.py` повторно получает их и проверяет хеши. `--refresh` разрешает намеренное обновление upstream-сборки, которое может сделать старые снимки несовместимыми. Происхождение ресурсов: `THIRD_PARTY_NOTICES.md`.
